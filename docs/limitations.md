# Limitations

- A [`Pipeline`](https://scikit-learn.org/stable/modules/generated/sklearn.pipeline.Pipeline.html) is ported to one source file, if all its preprocessing steps are supported transformers (e.g. a [`StandardScaler`](https://scikit-learn.org/stable/modules/generated/sklearn.preprocessing.StandardScaler.html) or a [`OneHotEncoder`](https://scikit-learn.org/stable/modules/generated/sklearn.preprocessing.OneHotEncoder.html), also if they change the number of features) and its final estimator is supported. The ported pipeline supports the languages and templates of its final estimator. With the template `exported` the JSON file contains the model data of the final estimator and the additional key `transformers` with the model data of each transformer (the trees of a forest are under the key `estimators`). A `ColumnTransformer` or a `FeatureUnion` is supported if the transformers of all its parts are supported, an unsupported transformer can't be ported. A pipeline with such preprocessing steps (also as the best estimator of a `GridSearchCV` or `RandomizedSearchCV`) therefore raises a `NotSupportedYetError`, because the predictions of the ported final estimator alone would differ from those of the pipeline. Steps which are skipped (`None` or `'passthrough'`) are allowed. To port the final estimator anyway, pass `ignore_preprocessing=True` (CLI: `--ignore-preprocessing`). The preprocessing steps are then ignored with a `UserWarning`, so you have to apply them to the input data of the ported estimator yourself, also to the samples of `make()` and `test()`:

  ```python
  est = Estimator(pipeline, language='c', ignore_preprocessing=True)
  est.test(pipeline[:-1].transform(x))
  ```
- [`RFE`](https://scikit-learn.org/stable/modules/generated/sklearn.feature_selection.RFE.html) and [`RFECV`](https://scikit-learn.org/stable/modules/generated/sklearn.feature_selection.RFECV.html) are ported as transformers only (`transform`, the selection of the features). Their methods `predict`, `predict_proba`, `decision_function` and `score`, which call the estimator fitted on the selected features (`estimator_`), aren't ported, so an `RFE` or `RFECV` as final step of a pipeline raises a `NotSupportedYetError`. Port the estimator `estimator_` separately and pass the transformed features of the ported selector to it, or use the selector as a preprocessing step of a pipeline with a separate final estimator:

  ```python
  pipeline = make_pipeline(
      RFE(LogisticRegression(), n_features_to_select=2), DecisionTreeClassifier()
  )
  Porter(pipeline.fit(x, y), language='java').port()
  ```
- Text transformers (e.g. a [`CountVectorizer`](https://scikit-learn.org/stable/modules/generated/sklearn.feature_extraction.text.CountVectorizer.html)) read documents instead of numbers. They can't be ported as a step of a `Pipeline` or as a part of a `ColumnTransformer` or `FeatureUnion` yet (this raises a `NotSupportedYetError`). Port the vectorizer and the final estimator separately and pass the output of the ported vectorizer (one line of transformed features per document) to the ported estimator, e.g. `./CountVectorizer < documents.txt | ./MultinomialNB`.
- The labels of the classes of a classifier must have the same type: integers (also booleans, which are ported as `0` and `1`), floating point numbers or strings. The integers must fit into 32 bits. Other labels (e.g. mixed types in an `object` array) raise a `NotSupportedYetError`, so encode them with a [`LabelEncoder`](https://scikit-learn.org/stable/modules/generated/sklearn.preprocessing.LabelEncoder.html) before training.
- Java limits the bytecode of a method to 64 KB. Large estimators ported to Java with the `attached` or `combined` template can therefore fail to compile with a `code too large` error. Use the `exported` template instead.
- The C# code of the templates `attached` and `combined` only uses language features of C# 7.3 and no dependencies, so it also works with older runtimes (e.g. .NET Framework or Unity). The template `exported` reads the JSON file with `System.Text.Json` (incl. `JsonNamingPolicy.SnakeCaseLower`), which requires .NET 8 or newer. `make()` and `test()` require the .NET SDK (the command `dotnet`): they compile the ported estimator directly with the C# compiler of the SDK and run it with `dotnet`.
- Sparse matrices are always converted to dense arrays, because the ported estimators only support dense data. This applies to estimators fitted on sparse data (e.g. [`SVC`](https://scikit-learn.org/stable/modules/generated/sklearn.svm.SVC.html) or [`KNeighborsClassifier`](https://scikit-learn.org/stable/modules/generated/sklearn.neighbors.KNeighborsClassifier.html)), to estimators converted with `sparsify()` (e.g. [`LogisticRegression`](https://scikit-learn.org/stable/modules/generated/sklearn.linear_model.LogisticRegression.html)) and to the samples passed to `make()` and `test()`. With many features (e.g. text features of a `TfidfVectorizer`) the dense model data, the ported source code and the exported JSON file can get very large, so make sure that enough memory (RAM) and disk space are available, both for porting and for compiling and running the ported estimator.
- The results of floating point functions like the power, the exponential or the logarithm can differ in the last digit (a few [ULP](https://en.wikipedia.org/wiki/Unit_in_the_last_place)) between scikit-learn and the ported estimators, because NumPy uses SIMD instructions depending on the CPU (e.g. AVX-512 on x86) and the languages use their own math libraries. So probabilities and predicted values can differ in the last digits, and samples on a decision boundary (e.g. two classes with the same probability or a score equal to the threshold of an outlier detector) can get different predictions. Use `test()` with representative samples to check how often the predictions match.
- `make()` and `test()` call the compiler and the interpreter of the target language directly (without a shell), but they are only tested on Linux. On Windows they show a warning and still try to compile and run the ported estimator. `port()` and `save()` work on all platforms.
